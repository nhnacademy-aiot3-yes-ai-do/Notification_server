# Notification 이벤트 계약 수집 현황

이 문서는 실제 Producer와 RabbitMQ 연동 전 확인해야 할 값을 기록한다. 담당자가 확정한 값을 받은 뒤 채우며, 임의의 예시값을 운영 설정으로 사용하지 않는다.

## 공통 이벤트 외피

```json
{
  "eventId": "UUID",
  "eventType": "SENSOR_ERROR",
  "producer": "rule-service",
  "targetType": "CULTIVATION",
  "targetId": 12,
  "occurredAt": "2026-07-27T10:30:00+09:00",
  "payload": {}
}
```

## Producer별 확인표

| Producer | 이벤트 | 실제 JSON | targetId 의미 | Exchange/Queue/Routing Key | 상태 |
|---|---|---|---|---|---|
| Rule | 환경 이상·복구 | 담당자 확인 필요 | cultivation_id 확인 필요 | 인프라 확인 필요 | 대기 |
| Rule | 센서 오류·오프라인 | 담당자 확인 필요 | cultivation_id 또는 sensor_id 확인 필요 | 인프라 확인 필요 | 대기 |
| Rule | 제어 실패 | 담당자 확인 필요 | cultivation_id 확인 필요 | 인프라 확인 필요 | 대기 |
| Cultivation | 수확 완료 | 담당자 확인 필요 | cultivation_id 확인 필요 | 인프라 확인 필요 | 대기 |
| Cultivation | 재배 종료 | 담당자 확인 필요 | cultivation_id 확인 필요 | 인프라 확인 필요 | 대기 |
| AI | 일일 피드백 완료 | 담당자 확인 필요 | cultivation_id 또는 user_id 확인 필요 | 인프라 확인 필요 | 대기 |
| Auth | 로그인 성공 | 담당자 확인 필요 | user_id 확인 필요 | 인프라 확인 필요 | 대기 |
| Inquiry | 문의 답변 완료 | 담당자 확인 필요 | user_id 또는 inquiry_id 확인 필요 | 인프라 확인 필요 | 대기 |

## 구현 전 필수 확인

- 실제 RabbitMQ host, port, username, password, vhost
- Exchange, Queue, Routing Key, DLQ
- 메시지 ACK/NACK 및 재처리 규칙
- `targetType`과 `targetId`의 최종 의미
- Producer payload의 필드명과 타입
- 시간대 포함 여부(`OffsetDateTime`으로 역직렬화 가능한지)
