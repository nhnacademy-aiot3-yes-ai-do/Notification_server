# Notification Service 검증 결과 및 회의 준비

작성일: 2026-07-28

## 1. 현재까지 검증 완료

### 도메인 테스트

- NotificationEndpoint: 생성, 활성화·비활성화, 삭제, 삭제 후 재활성화 방지, 정보 수정
- NotificationSubscription: 생성, 활성화·비활성화, 삭제, 삭제 후 재활성화 방지
- Notification: 이벤트 ID·payload·메시지 보관
- NotificationDelivery: 알림·구독·템플릿 연결, PENDING 초기 상태, 시도 횟수 0

현재 도메인 테스트 11개가 모두 통과한다.

### PostgreSQL Migration·Seed 검증

- 빈 검증용 PostgreSQL DB에서 V1~V5 전체 적용 성공
- 테이블 11개 생성 확인
- 기준 데이터 삽입 확인
  - channel_type: 2개
  - notification_event_type: 10개
  - subscription_target_type: 3개
  - notification_subscription_type: 10개
  - notification_template: 20개
- 동일 DB 재실행 시 `No migration necessary` 확인
- 재실행 후 기준 데이터 개수가 변하지 않아 중복 없음 확인

## 2. Repository 검증

`NotificationEndpointRepositoryTest`는 외부 PostgreSQL 검증 DB에 연결해 다음을 검증하도록 작성했다.

- 사용자별 조회 시 `is_deleted = false`인 Endpoint만 반환
- 다른 사용자의 Endpoint는 반환하지 않음
- 삭제된 Endpoint는 ID 조회에서도 제외

실행 명령:

```bash
mvn -Dnotification.integration.enabled=true test
```

기본 `mvn test`에서는 외부 DB에 의존하지 않도록 이 통합 테스트를 비활성화한다.
현재 검증용 PostgreSQL(`localhost:55432/notification_migration_test`)에 연결해 Repository 테스트
2개를 모두 통과했다. 다른 DB를 사용할 때는 `notification.integration.db-url` 등의 시스템 속성으로
접속 정보를 바꿀 수 있다.

## 3. 8월 3일 공동 회의에서 확정할 항목

아래 값은 현재 코드에 임의로 확정하지 않는다.

1. RabbitMQ Exchange 이름
2. Queue 및 DLQ 이름
3. Routing Key 규칙
4. Host·Port·Virtual Host·인증 정보
5. ACK/NACK 및 재처리 규칙
6. JWT 사용자 ID claim의 최종 이름(`userId` 또는 `sub` 등)
7. Cultivation 소유권 확인 API 호출 여부와 실제 응답 형식
8. Telegram Bot·Discord Webhook 테스트 발송 방법
9. 서비스 공통 API 오류 응답 형식

회의 전까지는 위 값을 임시값으로 배포하거나 다른 서비스와의 계약으로 간주하지 않는다.
