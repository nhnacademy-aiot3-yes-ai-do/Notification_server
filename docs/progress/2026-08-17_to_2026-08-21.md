- 동일 이벤트가 Discord·Telegram으로 여러 번 Delivery되어도 원본 `notification.id` 기준으로는 1건임

- RuleEngine의 임계값 이벤트 계약:
  - Exchange: `yes-nhn.notification.exchange`
  - Queue: `yes-nhn.notification.threshold.queue`
  - DTO: `ThresholdStatusChangedEvent`
  - 상태: `EXCEEDED`, `RECOVERED`
- 로컬·내부망 테스트 환경에서는 EXCEEDED/RECOVERED 이벤트가 Notification을 거쳐 Discord Webhook으로 발송되는 것을 확인함
- 운영 배포 환경 E2E와 Telegram 실제 발송은 별도 검증이 필요함
- AI 일일 피드백은 Notification PostgreSQL 이력을 조회하는 방향으로 정리
- Redis는 알림 원본 이력 저장소가 아니라 중복 방지·임시 상태 용도로만 고려

## AI 일일 집계 API 초안 (Documents 클론에만 존재)

민서님과 협의한 방향을 기준으로 Documents 클론에서 다음 기능의 초안을 구현했습니다.
IdeaProjects 클론에는 아직 반영하지 않았으며, 최종 계약 확정 전에는 이 클론에 병합하지 않습니다.

### 집계 기준

- 조회 기준: `cultivationId`와 `date`
- 하루 범위: 요청 날짜의 00:00 이상, 다음 날 00:00 미만
- 집계 대상: 해당 재배지에 연결된 Notification 원본 이벤트
- 이벤트 유형별 건수와 전체 건수를 함께 반환
- Discord·Telegram Delivery가 여러 개여도 `COUNT(DISTINCT notification.id)`로 1건 처리
- 현재 쿼리는 Delivery와 Subscription을 통해 재배지 대상을 필터링함

### 추가·수정 파일

- `NotificationRepository`
  - 날짜·재배지 기준 native aggregation query 추가
- `NotificationEventCountProjection`
  - 이벤트 유형 코드·이름·건수 projection
- `DailyNotificationEventCountResponse`
- `DailyNotificationSummaryResponse`
- `NotificationDailySummaryService`
  - 이벤트 유형별 결과를 DTO로 변환하고 전체 건수 합산
- `NotificationInternalController`
  - 내부용 API 분리
- `ValidationMessages`
  - 재배지 ID 양수 검증 메시지 추가
- `GlobalExceptionHandler`
  - 잘못된 날짜 형식 등 요청 타입 변환 오류를 400으로 응답

### 내부 API 초안

```http
GET /internal/api/v1/notifications/daily-summary?cultivationId=4&date=2026-08-20
```

예상 응답:

```json
{
  "cultivationId": 4,
  "date": "2026-08-20",
  "totalCount": 5,
  "eventCounts": [
    {
      "eventTypeCode": "ENVIRONMENT_THRESHOLD_BREACHED",
      "eventTypeName": "환경 이상",
      "count": 3
    },
    {
      "eventTypeCode": "ENVIRONMENT_RECOVERED",
      "eventTypeName": "환경 복구",
      "count": 2
    }
  ]
}
```

> `/internal` 경로는 AI 서비스와의 내부 호출용 초안입니다. 최종 Base Path, 인증 방식,
> Gateway 노출 여부는 팀 계약 확인 후 확정해야 합니다.
